PRD 2：nodeskclaw-task 后端修复方案
文档信息
文档名称：nodeskclaw-task AutoTask API 契约修复 PRD
版本：v0.5.2
适用项目：nodeskclaw-task
目标模块：AutoTask Dashboard / Task API / Worker API
优先级：P0
1. 背景

AutoTask 前端远程模式下，接口基础地址配置为：

taskBackendUrl: http://127.0.0.1:4520
taskPrefix: /api/v1/autotask

源码默认配置：

前端会通过 buildTaskUrl(config, path) 拼接远程任务接口。

当前前端实际调用路径包括：

GET /api/v1/autotask/dashboard/summary
GET /api/v1/autotask/tasks
GET /api/v1/autotask/rpa-workers
GET /api/v1/autotask/runs
GET /api/v1/autotask/artifacts
GET /api/v1/autotask/portal-accounts
GET /api/v1/autotask/workflow-templates

其中 Dashboard 远程调用来自 remoteApi.getDashboard()，路径为 /dashboard/summary。

任务列表远程调用来自 remoteApi.getTasks()，路径为 /tasks。

当前问题是：/api/v1/autotask/tasks 返回了统计摘要对象，而不是任务列表，导致前端语义错乱。

2. 目标

后端需要统一 AutoTask API 契约：

1. /dashboard/summary 返回 Dashboard 统计。
2. /tasks 返回任务列表。
3. 所有 API 使用统一响应 envelope。
4. 空数据必须返回空对象或空数组，不能省略字段。
5. 字段命名兼容前端 camelCase。
6. 后端日志需要能区分接口成功、业务空数据、契约错误。
3. 非目标
1. 不实现完整 RPA Worker 执行。
2. 不实现真实 Artifact 文件存储。
3. 不实现完整权限模型。
4. 不改变 auth 服务登录接口。
5. 不要求一次性实现所有 AutoTask 模块的完整业务逻辑。
4. API 统一响应格式

所有成功响应统一为：

{
  "code": 0,
  "error_code": null,
  "message_key": null,
  "message": "success",
  "data": {}
}

所有失败响应统一为：

{
  "code": 10001,
  "error_code": "AUTOTASK_TASK_NOT_FOUND",
  "message_key": "autotask.task.not_found",
  "message": "Task not found",
  "data": null
}

HTTP 状态码建议：

200：业务成功
400：请求参数错误
401：未登录或 token 无效
403：无权限
404：资源不存在
409：状态冲突
500：服务端异常
5. Dashboard API 契约
5.1 接口
GET /api/v1/autotask/dashboard/summary
5.2 职责

返回工作台统计，不返回任务列表明细。

5.3 响应结构：推荐标准结构
{
  "code": 0,
  "error_code": null,
  "message_key": null,
  "message": "success",
  "data": {
    "stats": {
      "pending": 0,
      "running": 0,
      "waitingHuman": 0,
      "failed": 0,
      "completedToday": 0,
      "successRate": 0.0,
      "onlineWorkers": 0
    },
    "taskTypeDistribution": []
  }
}
5.4 字段说明
stats.pending
  待执行任务数。
  可由 READY + QUEUED 统计得出。

stats.running
  RUNNING 状态任务数。

stats.waitingHuman
  WAITING_HUMAN / HUMAN_OPERATING 状态任务数。

stats.failed
  FAILED 状态任务数。

stats.completedToday
  今日 SUCCESS + SUCCESS_MANUAL + PARTIAL_SUCCESS 数量。

stats.successRate
  今日成功率。
  建议公式：
  completedToday / max(todayTotal, 1) * 100

stats.onlineWorkers
  在线 Worker 数。

taskTypeDistribution
  任务类型分布。
  空数据时必须返回 []。
5.5 兼容结构

如果短期内不想调整成嵌套结构，也可以继续返回扁平结构：

{
  "code": 0,
  "message": "success",
  "data": {
    "todayTotal": 0,
    "ready": 0,
    "running": 0,
    "waitingHuman": 0,
    "failed": 0,
    "success": 0,
    "successRate": 0.0,
    "onlineWorkers": 0,
    "taskTypeDistribution": []
  }
}

但必须至少补充：

"taskTypeDistribution": []

否则旧前端仍可能崩溃。

推荐采用标准结构，不建议长期保留扁平结构。

14. 后端实现要求
14.1 路由职责拆分
/autotask/dashboard/summary
  只返回 Dashboard 统计。

/autotask/tasks
  只返回任务列表。

/autotask/tasks/{id}
  返回单任务详情。

/autotask/rpa-workers
  返回 Worker 列表。

禁止：

/tasks 返回 Dashboard 统计。
dashboard summary 返回任务列表。
空数据时省略数组字段。
14.2 空数据规范

所有列表接口空数据必须返回：

"data": []

或：

"data": {
  "items": []
}

Dashboard 中数组字段必须返回：

"taskTypeDistribution": []
14.3 字段命名规范

建议直接返回 camelCase：

waitingHuman
successRate
taskTypeDistribution
completedToday

如果后端内部使用 snake_case，可以在 API response 层转换。

14.4 日志要求

每个接口记录：

method
path
status_code
user_id
trace_id
duration_ms
response_shape

示例：

GET /api/v1/autotask/dashboard/summary 200 shape=dashboard_summary duration=12ms
GET /api/v1/autotask/tasks 200 shape=list count=0 duration=8ms
15. 后端验收标准
15.1 Dashboard 空数据

请求：

GET /api/v1/autotask/dashboard/summary

响应必须包含：

{
  "data": {
    "stats": {
      "pending": 0,
      "running": 0,
      "waitingHuman": 0,
      "failed": 0,
      "completedToday": 0,
      "successRate": 0.0
    },
    "taskTypeDistribution": []
  }
}
15.2 Tasks 空列表

请求：

GET /api/v1/autotask/tasks

响应必须是：

{
  "code": 0,
  "message": "success",
  "data": []
}

不能是统计对象。

15.3 前端联调

用远程模式启动前端：

VITE_AUTOTASK_API_MODE=remote

登录后进入 Dashboard：

1. 页面不白屏。
2. 不出现 Cannot read properties of undefined。
3. Dashboard 统计正常显示 0。
4. 当前执行队列为空表格。
5. Worker 状态为空列表。
6. 后端日志无异常。
16. nodeskclaw-task Cursor 实施提示词
修复 nodeskclaw-task AutoTask API 契约。

目标：
1. /api/v1/autotask/dashboard/summary 返回 Dashboard 统计。
2. /api/v1/autotask/tasks 返回任务列表，空数据返回 data: []。
3. 所有成功响应使用 { code, error_code, message_key, message, data }。
4. Dashboard 返回 data.stats 和 data.taskTypeDistribution。
5. 空数组字段不得省略。
6. 字段优先使用 camelCase。

重点：
当前 /api/v1/autotask/tasks 疑似返回了 todayTotal/ready/running 等统计对象，这是错误的。统计对象应移动到 /dashboard/summary。

验收：
1. GET /dashboard/summary 返回 stats + taskTypeDistribution。
2. GET /tasks 返回 [] 或 items 列表。
3. copilot-autotask Dashboard 登录后不白屏。
