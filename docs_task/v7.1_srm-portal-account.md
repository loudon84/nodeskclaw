PRD B：nodeskclaw-task 后端 v0.6 方案
1. 版本定位

版本：v0.6

主题：PortalAccount 后端能力补齐 + AutoTask Remote API 稳定化

nodeskclaw-task 已经是 AutoTask 业务后端，负责 Portal Account、Workflow Template、Workflow Binding、Automation Task、RPA Run、Human Action、Artifact 及 Worker 调度等能力。 v0.6 后端重点不是重新设计后端，而是把前端需要的 客户 SRM 门户管理能力 稳定成可用 API。

2. 后端目标

v0.6 后端需要保证：

模块	v0.6 要求
PortalAccount	CRUD 可用
PortalAccessGrant	权限控制可用
test-open	可校验权限并返回打开上下文
统一响应	全接口 ApiResponse
租户隔离	基于 current_org_id
审计	创建、编辑、删除、打开 Portal 记录 AuditLog
前端联调	OpenAPI 与实际返回一致
Seed	提供可用于联调的真实 seed 数据
3. 后端非目标
不在 v0.6 做 RPA Flow 绑定 UI 专用接口
不在 PortalAccount 创建时保存明文密码
不做自动登录
不做验证码处理
不做浏览器会话恢复
不做 Worker Token 强化，保留到后续版本

Worker API 当前面向内网 RPA Engine，未挂载 JWT 依赖，生产环境需要后续通过网络策略或 Token 机制加固。

4. 数据模型要求

v0.6 继续使用已有模型：

PortalAccount
PortalAccessGrant
AuditLog
UserCache

现有数据模型已经包含 PortalAccount 与 PortalAccessGrant，其中 PortalAccount 对应 SRM/门户账号，PortalAccessGrant 用于 Portal 级权限授予。

4.1 PortalAccount 字段要求

建议后端确认以下字段稳定返回：

interface PortalAccount {
  id: string
  tenantId: string

  entityType: 'CUSTOMER' | 'SUPPLIER'

  erpEntityCode: string
  erpEntityName: string

  portalName: string
  portalUrl: string

  loginAccount: string

  clientOpenMode: 'webcontents' | 'system_browser'
  clientSessionPartition: string

  status: 'ENABLED' | 'DISABLED'

  createdBy: string
  createdAt: string
  updatedAt: string
}

v0.6 必填规则：

entityType 必填，客户 SRM 固定 CUSTOMER
erpEntityCode 必填
erpEntityName 必填
portalName 必填
portalUrl 必填，必须是 http/https URL
loginAccount 必填
clientOpenMode 必填
status 默认 ENABLED
clientSessionPartition 可由后端默认生成
4.2 唯一性约束

建议后端校验：

tenantId + entityType + portalUrl + loginAccount 唯一

错误：

{
  "code": 40900,
  "message_key": "errors.autotask.portal_account.duplicate",
  "message": "门户账号已存在",
  "data": null
}
5. PortalAccount API 设计

nodeskclaw-task 已经声明 Portal Account 的列表、创建、详情、更新、删除、test-open、access-grants 接口。 v0.6 要求把这些接口作为前端正式合同。

5.1 列表
GET /api/v1/autotask/portal-accounts

建议支持 query：

参数	类型	说明
entityType	string	CUSTOMER / SUPPLIER
status	string	ENABLED / DISABLED
keyword	string	匹配客户名称、门户名称、账号、URL
page	number	默认 1
pageSize	number	默认 20

v0.6 可以先返回数组；但建议尽快统一分页：

{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "pageSize": 20
  }
}

若保持当前数组返回，则前端先兼容：

type ListResponse<T> = T[] | { items: T[]; total: number; page: number; pageSize: number }
5.2 创建
POST /api/v1/autotask/portal-accounts

请求：

{
  "entityType": "CUSTOMER",
  "erpEntityCode": "CUST-001",
  "erpEntityName": "示例客户 A",
  "portalName": "客户 A SRM 生产环境",
  "portalUrl": "https://portal.example.com/srm",
  "loginAccount": "buyer@example.com",
  "clientOpenMode": "webcontents",
  "clientSessionPartition": "persist:portal-cust-001",
  "status": "ENABLED"
}

后端行为：

校验 JWT
解析 tenantId
校验 PORTAL_EDIT 或 Portal 管理权限
校验唯一性
默认生成 clientSessionPartition
写入 PortalAccount
创建默认 PortalAccessGrant 给 createdBy
写 AuditLog
返回 PortalAccount
5.3 更新
PATCH /api/v1/autotask/portal-accounts/{id}

后端行为：

校验 PORTAL_EDIT
禁止跨 tenant 更新
禁止更新 deleted_at 不为空的数据
变更 portalUrl/loginAccount 时重新做唯一性校验
写 AuditLog
5.4 删除
DELETE /api/v1/autotask/portal-accounts/{id}

后端行为：

校验 PORTAL_EDIT
执行软删除 deleted_at
禁用相关 access grant 或保留但查询过滤
写 AuditLog
返回 success
5.5 test-open
POST /api/v1/autotask/portal-accounts/{id}/test-open

v0.6 建议返回打开上下文，而不是只返回 ok：

{
  "code": 0,
  "message": "success",
  "data": {
    "portalAccountId": "portal-001",
    "portalName": "客户 SRM 门户",
    "portalUrl": "https://portal.example.com/srm",
    "clientOpenMode": "webcontents",
    "clientSessionPartition": "persist:portal-001",
    "status": "ENABLED",
    "allowed": true
  }
}

后端行为：

校验 PORTAL_OPEN_WEB
校验 status === ENABLED
写 AuditLog: portal_account.test_open
不返回密码
不返回 credentialRef 明文
6. 权限设计

后端已经定义 Portal 权限码：

权限码	v0.6 用途
PORTAL_VIEW	查看客户 SRM
PORTAL_EDIT	新增、编辑、删除
PORTAL_OPEN_WEB	快速打开
PORTAL_MANAGE_PERMISSION	管理授权
PORTAL_VIEW_TASKS	后续从 Portal 查看任务

这些权限码已在 nodeskclaw-task 接口说明中定义。

v0.6 权限规则：

列表：只返回当前用户有 PORTAL_VIEW 的 PortalAccount
详情：需要 PORTAL_VIEW
创建：需要模块级 Portal 管理权限，或后端默认允许有租户管理角色的用户
编辑：需要 PORTAL_EDIT
删除：需要 PORTAL_EDIT
test-open：需要 PORTAL_OPEN_WEB
授权：需要 PORTAL_MANAGE_PERMISSION
7. 租户隔离

所有 Client API 必须使用当前登录用户的 current_org_id 作为 tenant_id。用户没有组织时返回 403。该规则已在 nodeskclaw-task 说明中定义。

后端实现要求：

任何 PortalAccount 查询必须带 tenant_id 条件
任何更新/删除必须校验 portal.tenant_id == current_user.current_org_id
任何 access grant 查询也必须限制 tenant_id
8. 审计日志

v0.6 后端应补齐审计：

操作	AuditLog action
创建 Portal	portal_account.created
编辑 Portal	portal_account.updated
禁用 Portal	portal_account.disabled
删除 Portal	portal_account.deleted
快速打开	portal_account.opened
新增授权	portal_account.access_granted

AuditLog 当前是 nodeskclaw-task 的业务表之一。

P3：联调支持
1. Seed 增加至少 3 条 CUSTOMER PortalAccount
2. Seed 增加当前测试用户的 PortalAccessGrant

5. 增加 CORS 支持 Electron dev origin
10. 后端验收标准

v0.6 后端验收：

1. GET /portal-accounts 能返回当前租户可见 Portal。
2. POST /portal-accounts 能创建 CUSTOMER Portal。
3. PATCH /portal-accounts/{id} 能更新 Portal。
4. DELETE /portal-accounts/{id} 执行软删除。
5. POST /portal-accounts/{id}/test-open 能返回 portalUrl、clientOpenMode、clientSessionPartition。
6. 无 PORTAL_OPEN_WEB 权限时 test-open 返回 403。
7. 无 PORTAL_EDIT 权限时 PATCH/DELETE 返回 403。
8. 重复 portalUrl + loginAccount 返回 409。
9. 所有响应保持 ApiResponse 包装。
10. data 字段保持 camelCase。
11. OpenAPI 与前端实际调用一致。
