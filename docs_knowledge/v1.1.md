# 1. 版本定位

PRD v1.0 已完成 `nodeskclaw-knowledge` 基础领域模型和服务骨架。

v1.1 的目标不再是“把功能代码创建出来”，而是：

> 将 v1.0 的同步式原型升级为能够连接真实 RAGFlow、正确处理异步解析、文件版本、动态权限和安全检索，并能够由 `copilot-knowledge` Desktop 切换到 Remote 模式实际使用的 Knowledge Backend。

v1.1 完成后的核心闭环：

```text
nodeskclaw Member
        ↓
KnowledgeBase
        ↓
ACL
        ↓
文件上传
        ↓
SourceFile / Version
        ↓
RAGFlow Document
        ↓
Metadata
        ↓
异步 Parse Worker
        ↓
DONE
        ↓
ACTIVE Version
        ↓
KnowledgeSet
        ↓
Secure Retrieval Planner
        ↓
RAGFlow Retrieval
        ↓
Active Version + ACL Cleaner
        ↓
Safe Chunks
        ↓
LLM
        ↓
Answer + Citation
        ↓
Copilot Knowledge Desktop
```

# 3. v1.1 核心目标

本版本必须完成六项能力：

### G1. 真实异步入库闭环

不能把“RAGFlow 已接受解析请求”等价于“文档已完成索引”。

必须等待：

```text
RAGFlow Document.run == DONE
```

后才能：

```text
SourceFile.active_version_id = new_version
```

---

### G2. Active Version 成为强一致安全边界

任何进入 LLM 的 Chunk 必须属于：

```text
SourceFile.active_version_id
```

仅拥有相同：

```text
nk_source_file_id
```

不再足够。

---

### G3. 完整 KnowledgeSet 权限体系

KnowledgeSet 本身需要：

```text
READ
USE
UPDATE
DELETE
MANAGE
MANAGE_ACL
```

但 KnowledgeSet 权限不得提升底层 KnowledgeBase / SourceFile 权限。

---

### G4. 正确的多 KnowledgeBase Retrieval Planner

必须支持：

```text
KB-A：全部可读
+
KB-B：部分文件可读
+
KB-C：全部不可读
```

而不是使用一个错误的：

```text
dataset_ids + document_ids
```

请求表达整个组合。

---

### G5. Desktop Remote API

使：

```text
copilot-knowledge
VITE_KNOWLEDGE_DATA_MODE=remote
```

能够真正使用：

```text
nodeskclaw-knowledge
```

而不是 Mock Repository。

---

### G6. Secure Knowledge Chat

在 Secure Retrieval 之后增加：

```text
Safe Chunks
    ↓
nodeskclaw-llm-proxy
    ↓
Answer
    ↓
Citation
```

LLM 永远不能直接看到未经 Knowledge Security Cleaner 的 RAGFlow Result。

# 6. 新 Ingestion 状态机

定义：

```text
PENDING
UPLOADING
RAGFLOW_UPLOADED
METADATA_SYNCED
PARSE_DISPATCHED
PARSING
VALIDATING
ACTIVE

FAILED
CANCELLED
```

其中：

```text
PARSE_DISPATCHED
```

表示：

> RAGFlow 已接受解析任务，但尚未确认任务开始。

状态转换：

```text
PENDING
   ↓
UPLOADING
   ↓
RAGFLOW_UPLOADED
   ↓
METADATA_SYNCED
   ↓
PARSE_DISPATCHED
   ↓
PARSING
   ↓
VALIDATING
   ↓
ACTIVE
```

失败：

```text
任何阶段
 ↓
FAILED
```

取消：

```text
PARSING
 ↓
CANCELLED
```

# 15. Metadata 一致性验证

Chunk 返回：

```json
{
  "document_id": "rag_doc_02",
  "document_metadata": {
    "nk_source_file_id": "sf_01",
    "nk_file_version_id": "version_02"
  }
}
```

本地查：

```text
rag_doc_02
→ version_02
→ sf_01
```

必须完全一致。

出现：

```text

```

或者：

```text

```

则：

```text
DROP CHUNK
+
SECURITY AUDIT
```

不能相信 RAGFlow metadata 覆盖本地 Registry。

# 18. 为什么本地 Active Check 仍必须保留

即使执行：

```text
RAGFlow enabled=0
```

也不能把它当最终安全保障。

因为可能：

```text
本地切换成功
↓
网络故障
↓
RAGFlow disable v1 失败
```

此时：

```text
RAGFlow v1
RAGFlow v2
```

都可能返回。

但 Chunk Cleaner 必须保证：

```text
v1 != source_file.active_version_id
→ DROP
```

因此：

```text
本地 Version Registry = Security Authority
RAGFlow enabled         = Retrieval Optimization
```

# 33. 为什么必须拆 Slice

例如：

```text
KB-A
→ 全部可读

KB-B
→ 只允许 doc-B1 / doc-B3
```

正确请求必须分别是：

```text
Request 1:
dataset_ids = [A]

Request 2:
dataset_ids = [B]
document_ids = [B1, B3]
```

再合并。

不能使用：

```text
dataset_ids=[A,B]
document_ids=[B1,B3]
```

表示这两种权限。

# 90. v1.1 最终验收标准

以下全部必须成立：

```text
01. RAGFlow parse_documents 返回成功不能直接标记 ACTIVE。

02. 只有 RAGFlow DONE 的 Version 可以 ACTIVE。

03. 一个 SourceFile 最多一个 Active Version。

04. Superseded Version Chunk 永远不能进入最终结果。

05. 即使旧 RAGFlow Document 未成功 disable，本地 Cleaner 仍能拦截。

06. RAGFlow metadata 与本地 SourceFile Registry 冲突时必须 DROP。

07. KnowledgeSet 拥有独立 READ / USE / MANAGE ACL。

08. KnowledgeSet USE 不提升 KB/File 权限。

09. 未授权用户不能 bind/unbind KnowledgeBase。

10. Full KB + Partial KB 可以正确联合检索。

11. KnowledgeSetItem weight 真正影响结果排名。

12. 相同 KnowledgeSet 中继续要求统一 Embedding Model。

13. ACL 修改无需重新 Parse / Embedding 即可生效。

14. KnowledgeBase 删除失败不会静默造成 Local/RAGFlow 漂移。

15. SourceFile 删除失败可由 Reconciliation 恢复。

16. Retrieval 返回的所有 Chunk 都已经通过 Active Version + ACL 两层检查。

17. LLM Context 只能由 SafeChunks 构造。

18. Unauthorized Chunk 不得进入 Prompt、Answer Citation 或 Chat Context。

19. Citation 原文件访问始终重新执行当前 ACL。

20. Desktop 不接触 RAGFlow API Key。

21. Knowledge Service 不再需要复制用户表。

22. Principal 继续使用 OrgMembership.id。

23. 被停用或必须修改密码的账户无法使用 Knowledge API。

24. Ingestion Worker 重启后任务能够继续处理。

25. API 支持真实 Upload Job 状态查询。

26. Desktop KnowledgeBase 页面可以切 Remote。

27. Desktop KnowledgeSet 页面可以切 Remote。

28. Desktop Document / Upload 页面可以切 Remote。

29. Desktop Chat 可以通过 Secure Knowledge Chat 完成真实问答。

30. RemoteKnowledgeRepository 核心方法不再返回 NOT_IMPLEMENTED。

31. `/health/ready` 能识别 DB / RAGFlow / Backend 不可用。

32. Docker Compose 可以启动 Knowledge API + Worker。

33. RAGFlow 本身零源码修改。

34. RAGFlow DB 零直接访问。
```
